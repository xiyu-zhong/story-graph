# 故事图谱：跨媒介产品模板 v0.1

> 状态：历史讨论草案，保留设计推导。当前设计以 [产品设计规范 v1.0](产品设计规范-v1.0.md) 与 [视觉素材规范 v1.0](视觉素材规范-v1.0.md) 为准；本文不再作为实施基线。全部文档见 [索引](README.md)。
> 延续用户明确的方向：以流程图、人物关系图、地图为核心；点击内容单元可阅读其完整故事；未来可扩展到小说、电影、电视剧等。
> 本文是对 [产品方案 v1](产品方案-v1.md) 的补充，不覆盖原文件。版本、粒度、版权、首批媒介范围等建议仍需确认。

## 1. 产品定位与设计原则

**把作品变成可以顺着故事走、从人物切入、从地点探索的交互式图谱。**

三张图是三个平级入口，不是搜索页的附属功能。完整故事叙述是三图共同连接的内容主体。

- 流程图：作品如何展开、具体发生了什么。
- 关系图：有哪些人物、他们有什么联系、关系如何变化。
- 地图：故事在哪里发生、人物如何移动、不同故事如何在空间上交汇。
- 内容详情：章节、场景或剧集的完整叙述，以及与三图对应的事件。

设计原则：

1. 统一故事对象与交互规则，不强迫所有媒介使用同样的层级名称和排版。
2. 内容完整收录与细节同时铺开是两回事，支持多层展开、缩放与聚焦。
3. 所有事实与叙述属于明确的作品版本，不能默认跨改编共用。
4. 选中对象、探索位置、已读/已看进度相互区分。
5. 文本事实、人物说法、编辑解读和推测明确区分。
6. 先验证少量固定模板，不建设任意配置的万能模板引擎。

## 2. 内容层级：从“章节”升级为“内容单元”

### 2.1 建议的组织方式

```text
作品集合（可选：同系列、改编关联）
  └─ 作品
      └─ 作品版本
          └─ 内容单元树
              ├─ 卷 / 章 / 段落
              ├─ 幕 / 段落 / 场景
              └─ 季 / 集 / 场景

内容单元通过来源位置连接事件；事件再连接人物、关系、地点等对象。
```

这是建议采用的产品约定，不宣称是所有影视资料库都通用的分类标准。

| 层级 | 定义 | 示例与边界 |
|---|---|---|
| 作品集合 | 方便发现、导航和对比的关联集合 | 同名原著与影视改编可放在同一集合，不代表共用剧情事实 |
| 作品 | 一次独立创作或改编的叙事作品 | 原著小说、改编电影、改编电视剧分别建作品；电视剧默认整部剧为一个作品 |
| 作品版本 | 具体编辑、翻译、剪辑或发行版本 | 小说译本、删节本；电影院线版、导演剪辑版 |
| 内容单元 | 作品内部的可导航层级 | 卷、章、季、集、场景；允许层级省略 |
| 来源位置 | 某条内容在这个版本中的具体位置 | 第几章及段落；某集内起止时间码 |
| 事件 | 故事里发生的一件可描述的事情 | 结盟、交涉、抵达、发现线索；不等同于一个场景或一个章节 |

### 2.2 三种媒介的默认预设

| 项目 | 小说 | 电影 | 电视剧 |
|---|---|---|---|
| 导航层级 | 卷 → 章，可省略卷 | 叙事段落 → 场景，可省略段落 | 季 → 集 → 场景，可省略季 |
| 流程图默认层级 | 章 | 场景或编辑整理的故事段落 | 集 |
| 详情页主单位 | 章 | 场景/段落；上层可看整片故事 | 集；可下钻场景 |
| 进度表达 | 已读完某章，未来可细到段落 | 当前版本看到某时间点 | 某季某集内的时间点 |
| 来源锚点 | 章、段落；页码仅适用于明确版本 | 当前剪辑版本内的时间码 | 当前版本、季集标识及集内时间码 |
| 专属补充 | 译名、注释、卷章结构 | 片长、剪辑版、演职员关联 | 季集编号、单集片长、连载状态 |

电影中的“幕”不一定是官方划分。编辑整理的幕、故事段落和场景标题，应标记为编辑整理；无需强行套三幕结构。电视剧也不必每集遵循统一戏剧结构。

### 2.3 不要绑定为“一章只能包含自己的事件”

一个事件可能被分散讲述、回忆或从不同视角重新展示；一个场景也可能包含多个事件。

因此：

- 事件有自己的标识，来源位置单独记录，可连接多个内容单元。
- 每次提及或展示都可以揭示不同的信息，不把事件第一次出现当作全部信息解锁。
- 是否为同一事件需要审校确认；有矛盾的叙述不能强行合并成唯一真相。
- 首版可仅支持简单事件，但不要把存储与交互设计成永久的一对一结构。

## 3. 通用对象：统一含义，不无限增加字段

| 对象 | 最少需要表达什么 | 重要边界 |
|---|---|---|
| 作品版本 | 当前内容对应哪一版、来源和覆盖范围 | 时间码、段落、进度不能脱离版本 |
| 内容单元 | 类型、标题、父级、顺序、内容范围 | 原作标题与编辑标题分开 |
| 事件 | 发生了什么、谁参与、涉及哪里、来源位置 | 顺序不自动代表因果；场景不自动等于事件 |
| 故事人物 | 角色身份、已知称呼、所处状态、参与事件 | 真实身份和别名可能晚于人物登场才揭晓 |
| 势力/群体 | 组织、家庭、团队及成员关系 | 成员归属可能多重、变化或尚不明确 |
| 人物关系 | 双方、关系语义、方向、成立依据和变化 | 单方怀疑不等于双方敌对；全书关系与当前关系区分 |
| 故事地点 | 名称、上级空间、地图定位方式、相关事件 | 不要求都能落到真实经纬度；不能与取景地混用 |
| 信息条目 | 具体陈述、来源、何时揭示、陈述性质、审核状态 | 可用于简介、身份、关系解释等，避免一段终局简介贯穿全书 |

可选扩展：物品、线索、世界规则、演员、拍摄地、成长阶段。只有作品或媒介需要时才显示，不把所有扩展都放入默认人物图。

演员是现实中的演职人员，角色是故事中的人物；通过出演关系关联。一个演员可饰演多角，一个角色也可由多人出演。不能用同一个演员节点替代多个故事人物。

## 4. 六类页面模板

### 4.1 作品入口模板

必需信息：

- 作品名称、媒介类型、作者/导演等适用的创作信息。
- 当前版本，可切换但明确说明切换影响。
- 内容覆盖范围：全量/部分；已发布、待审校、未制作分开。
- 三个平级入口：流程图、人物关系、地图。
- 继续上次探索，以及当前已读/已看进度。
- 全貌探索/跟随阅读或观看模式。
- 叙述来源与素材权利说明入口。

可选信息：所属系列、关联改编、收藏、内容更新说明。

不要把“尚未制作”伪装成“未来剧情未解锁”。连载作品的未知后续不应由系统猜测补齐。

### 4.2 内容单元详情模板

适用于小说章节、电影段落/场景、电视剧单集。

```text
【单元身份】
作品 / 版本 / 卷章、季集或场景编号 / 来源范围
原作标题或编辑整理标题

【快速概览】
本单元讲什么
主要人物 / 地点 / 涉及叙事线

【完整故事】
按叙事顺序完整讲述本单元内容
必要的上下文、行动、冲突、转折和结果
人物与地点可点击；段落能关联到具体事件

【事件结构】
可展开的事件链；多线叙事按需要分组

【本单元变化】
人物登场、关系变化、地点变化、目标或问题变化
仅列出实际发生的变化，没有则不强行生成

【前后连接】
承接哪些已知事件 / 前一单元 / 后一单元
影响后文的内容仅在允许的范围和模式下显示

【内容依据】
来源位置、整理/解读标识、纠错入口
```

完整故事的建议定义：独立整理的完整情节叙述，覆盖关键行动、动机、冲突与结果，不承诺逐字复刻原作，也不能虚构缺失细节。若产品选择提供原文或原视频，应另行建立授权内容与播放/阅读能力。

章节/场景模板中的结构是编审检查项，不要求每章都有冲突、反转或完整结局。

### 4.3 事件详情模板

- 简明标题、发生经过。
- 所属版本与全部相关来源位置。
- 参与人物及作用，不只是人物名单。
- 发生地点；回忆、转述、梦境等叙述性质。
- 故事时间：精确值、范围、相对顺序或未知。
- 前因与后果；明确因果、推断关联分开。
- 造成的关系、人物状态或地点状态变化。
- 展示本次叙述已经揭示的内容，不自动引入后续重述揭示的真相。

### 4.4 人物详情模板

- 当前范围内可展示的姓名、称呼、身份。
- 人物介绍；全貌介绍与阶段介绍分开。
- 所属势力/群体及变化。
- 局部关系图，与全书图的定位入口。
- 参与事件/内容单元列表，点击可进入个人故事线。
- 到访地点与旅程。
- 可选成长、目标、立场变化；推断内容标明解读。
- 影视专属：出演信息，默认不把演职员信息混入故事关系图。

### 4.5 关系详情模板

- 双方人物或群体，关系方向与语义。
- 当前状态，或者明确标记为全书历史关系。
- 建立关系的故事依据。
- 共同经历，以及发生变化的节点。
- 可以跳到具体章节、场景和地点。
- 对争议、单方认知、伪装关系保留叙述语境，不用单个敌友标签覆盖。

### 4.6 地点详情模板

- 名称、故事内属性、上级区域和下级地点。
- 地理/空间定位方式：真实坐标、示意位置、平面布局或未知。
- 在此发生的事件、相关章节/场景与到访人物。
- 多次到访记录，保留每次关联的故事位置。
- 当前筛选人物的来路与去向；缺少依据时不画确定旅程。
- 可选：地点随时间的变化。
- 影视取景信息作为独立扩展，明确标注不等于故事发生地。

## 5. 三图模板与联动规则

### 5.1 流程图

- 全部内容单元可访问，按作品 → 段落/卷/季 → 章/集/场景 → 事件逐层展开。
- 默认遵循作品的呈现顺序；可显示回忆、插叙、平行叙事标记。
- 顺序线、因果线、叙事分支线使用不同语义和图例。
- 多泳道用于人物线/叙事线，不默认把每个人物都做成一条泳道。
- 未来可增加故事时间顺序；时间不确定或并行时，不强行生成精确总排序。

### 5.2 人物关系图

- 全部人物可收录和访问，分组展开与局部聚焦解决规模问题。
- 支持全貌关系、当前阶段关系两种明确状态。
- 点击人物查看人物故事线；点击连线查看关系经历。
- 新增或变化可突出显示；尽量保持已有节点布局稳定。
- 线条不能仅靠颜色区分；关系标签、方向和图例要清楚。

### 5.3 地图

把“地图”设计为故事空间的表达，至少预留四种固定预设：

1. 真实地理地图：城市、地区、旅行路线。
2. 架空世界地图：世界、区域、城镇逐级展开。
3. 建筑/室内空间图：宅邸、房间、楼层、列车车厢等。
4. 地点拓扑图：空间位置不确定，但地点连接或移动关系有依据。

地图分两种顺序：沿叙事浏览地点、沿人物追踪旅程。剪辑从甲城切到乙城，不等于人物从甲城移动到了乙城。

允许“尚无足够空间信息”的状态，展示已知地点与信息缺口，不为了填满地图而编造坐标或路线。

### 5.4 共用探索状态

始终明确：当前作品版本、展开层级、当前内容单元、选中对象、视图筛选、全貌/跟随模式。

| 操作 | 流程图 | 关系图 | 地图 | 详情 |
|---|---|---|---|---|
| 选内容单元 | 定位并可展开事件 | 突出相关人物和关系变化 | 突出涉及地点 | 完整故事 |
| 选事件 | 定位关联单元 | 突出参与人物 | 定位故事发生空间 | 事件经过与依据 |
| 选人物 | 突出参与单元 | 突出关系网络 | 展示有依据的到访记录 | 人物故事线 |
| 选关系 | 突出相关事件 | 展开关系演变 | 按需突出共同事件地点 | 共同经历 |
| 选地点 | 突出相关单元 | 突出相关人物 | 聚焦地点与空间层级 | 地点故事 |

选择对象不自动重排三图、不自动改变已读/已看进度。提供返回、面包屑、清除筛选；聚焦移动可取消或恢复。

## 6. 三种时间与两种进度状态

### 6.1 时间概念必须分开

| 概念 | 用途 | 示例 |
|---|---|---|
| 叙事位置 | 作品按什么顺序讲述，用户看到哪里 | 小说某章、电影某分钟、某季某集内某时间 |
| 故事时间 | 事件在故事世界里何时发生 | 十年前、同一天、某事件之后；允许未知和范围 |
| 信息揭示位置 | 某条身份、关系或事实何时对读者/观众可知 | 人物早已出现，但某个身份到后段才揭晓 |

回忆中的事件不能因为发生得早就提前解锁；同时发生也不等于在作品中相邻展示。

### 6.2 探索位置与消费进度分开

- 探索位置：用户现在正在看哪一章、哪一集、哪一个节点。
- 已读/已看记录：用户明确读完/看过哪些内容，是安全展示范围的依据。

小说：默认“已读完某章”，不是含糊的“读到某章”。
电影：记录到具体版本的时间位置；某场景只看了一半时，不能自动展示场景后半段事件。
电视剧：季、集、集内位置共同定位；不能只有一个跨全剧的“第 N 集”。

首版可以只支持连续阅读/观看边界，但要明确提示这种约定。以后支持跳集和非连续观看时，需要单独记录已看范围，不能以最远位置默认推断前面全部看过。跨版本进度迁移必须有明确映射；无法可靠映射时让用户重新确认，不按片长比例换算。

### 6.3 两种模式

- 全貌探索：用户主动选择看已收录的完整作品内容，可包含后续情节。
- 跟随阅读/观看：依据当前已知范围展示信息，搜索、标题、关系、地图、分享预览都遵守同一边界。

“内容尚未制作”“来源不确定”“未读内容隐藏”使用不同文案，不相互混淆。首次进入不应默认假定已读完第一章或已看完第一场景。

## 7. 版本、改编与跨作品关联

### 7.1 必须现在约定的边界

- 原著人物与改编角色不直接共享一份状态、事件和关系。
- 同名人物可能被删减、拆分或合并；人物对应允许一对多、多对一、缺失与待确认。
- 不同剪辑版本可能包含不同场景或叙事顺序，同一个时间码不能直接复用。
- 内容提取和用户进度都必须绑定版本，不能只绑定作品名。
- “同系列”或“同一宇宙”仅是导航/连续性标记，不自动允许合并所有剧情事实。

### 7.2 后续可做的跨媒介体验

- 原著某章对应改编的哪些场景/剧集。
- 某个人物在不同版本中的身份与经历差异。
- 新增、删除、合并、重排的情节对照。
- 同一事件在不同版本中的叙述方式。

这些依赖经过审校的对应关系，不承诺自动一对一对齐，也不是首版必需能力。

## 8. 内容生产与模板填写规则

统一模板要同时约束前台和编辑流程，否则前台一致但内容质量不一致。

建议流程：

1. 登记作品、版本、来源和使用权边界，明确是否允许全文、图片、片段等素材。
2. 建立真实的内容单元目录与来源锚点；编辑分段标明来源性质。
3. 整理事件、人物、地点及信息揭示位置，再生成完整叙述。
4. 审核人物消歧、事件归并、关系语义、地点移动与版本隔离。
5. 以具体进度预览三图和详情，检查提前泄露与跨图不一致。
6. 标注覆盖范围，发布；反馈进入人工处理，不直接修改公开事实。

编辑规范：

- 不把系统知道的全书真相写进早期人物简介。
- 每条关系与关键陈述可追溯到来源位置；低把握内容进入待审而非默认发布。
- 提取输出中保留未知，不要求模型把所有模板槽位填满。
- 对影视，字幕不一定覆盖无对白动作、空间关系、画面揭示等信息；不能把仅字幕抽取宣称为完整理解。
- 事实错误、版本错误、疑似剧透、地点/路线错误分开收集。
- 封面、剧照、地图、字幕、视频片段和原作文本分别管理来源与使用许可；不存在通用的安全字数或片段时长。
- 链接到来源时仅使用实际支持的链接；不假定任意播放平台支持精确时间跳转。

模板本身维护版本号和字段说明；模板变更先用样本验证，不静默改变已发布内容的含义。产品阶段用文档或表格维护即可，不必先建复杂配置后台。

## 9. 页面框架与交互预设

```text
作品 / 版本 / 内容范围 / 探索模式

[ 流程图 ]  [ 人物关系 ]  [ 地图 ]

主画布：任意一图都可以成为主视图
  + 可选联动辅窗
  + 内容详情区，可展开为宽阅读区

当前选中对象 / 返回路径 / 进度与探索位置
```

- 桌面：主图探索与三图联动总览两种布局；不要求三图永远平分屏幕。
- 手机：三图切换共享同一选中状态，详情可全屏展开，不强塞三个缩小画布。
- 流程图的粒度切换与地图的空间层级切换应清晰可见。
- 每张图都有图例、当前位置和恢复视野入口。
- 动画用于表达变化，不依赖自动播放才能理解；可以关闭或减少。
- 允许隐藏图片和视频；产品核心不依赖尚未取得授权的影视素材。

## 10. 值得丰富的玩法与适用条件

| 方向 | 体验 | 适用与限制 | 阶段建议 |
|---|---|---|---|
| 故事走读 | 点击下一事件，故事、人物、地图同步推进 | 三图共同的核心体验；手动控制即可 | 首个原型 |
| 人物专属故事线 | 从人物出发看参与事件和旅程 | 保留原内容单元上下文 | 首版增强 |
| 阶段变化对比 | 两个章节/集数之间有哪些新增人物、关系和地点变化 | 只比较同一版本中的可用内容 | 首版增强 |
| 地点历史 | 在同一地点按故事阶段浏览发生过的事 | 叙事浏览与真实故事时间分开 | 后续 |
| 关系演变 | 沿共同事件理解相识、结盟、冲突等变化 | 明确关系方向与依据 | 首版增强 |
| 悬疑线索图层 | 线索首次呈现、人物说法、后续解释彼此连接 | 可作为事件/物品扩展；跟随模式严格限制揭示范围 | 后续专题 |
| 知情范围对照 | 区分观众知道什么、某人物当时知道什么 | 信息建模和审校成本高，不纳入通用必填项 | 高阶实验 |
| 原著与改编对照 | 对照章节、场景、角色与情节改动 | 要有明确对应和独立版本事实 | 后续 |
| 世界观层级探索 | 从世界到地区、城市、建筑逐层进入 | 地理与拓扑都可用；保留不确定性 | 按作品启用 |
| 读后因果与伏笔 | 连接铺垫、揭示和后果 | 主动开启的读后模式；编辑解读单独标明 | 后续 |

目标、悬念、冲突等可以作为编审提示和可选图层，不应该强迫所有作品与内容单元使用同一戏剧公式。

## 11. 用小样本检验模板，而不是同时完整制作三种媒介

建议先用原创测试内容，或来源和权利状态清楚的材料，准备三个结构样本：

1. 小说样本：数个连续章节，包含关系变化与地点移动。
2. 电影样本：数个场景，包含一次回忆或交叉剪辑。
3. 电视剧样本：数集内容，至少验证跨集故事线，以及不同季内集号重复的情况。

这三个样本用来检查模板是否兼容，不代表首发必须同时上线小说、电影和电视剧。

关键验收情境：

| 情境 | 应有结果 |
|---|---|
| 一次事件在后面被重新讲述 | 保留多个来源位置，不提前公开后面才揭示的信息 |
| 电影剪辑从城市甲切到城市乙 | 可在流程中切换地点，不自动生成某人的旅行路线 |
| 故事主要发生在一栋楼里 | 地图使用楼层/房间布局，而不是无意义的世界地图 |
| 同一演员饰演两个人物 | 两个故事人物独立存在，出演信息单独关联 |
| 原著与电视剧对人物身份设定不同 | 两个作品的事实隔离，对比时明确差异 |
| 切换导演剪辑版 | 提醒版本变化，不静默沿用原时间码和观看位置 |
| 选中某个场景 | 三图和完整故事指向同一对象，但不自动确认已看完 |
| 只看到某场景中途 | 不展示后半段事件及后续才明确的关系 |
| 某地点只在回忆或台词里出现 | 明确标注，不算作当前人物真实到访 |
| 连载尚未更新或整理尚未完成 | 说明内容状态，不生成猜测剧情，不与防剧透隐藏混淆 |

## 12. 现在定什么，什么可以以后再定

### 现在定好，避免后续返工

- 三图作为平级核心入口，完整故事作为共同内容主体。
- 作品、版本、内容单元、事件的区别。
- 小说/电影/电视剧三种固定预设及缺失状态。
- 六类详情模板与完整故事的内容定义。
- 角色与演员、故事地点与取景地、原著与改编的边界。
- 来源锚点、叙事位置、故事时间、信息揭示位置的区别。
- 三图联动规则，以及探索位置不等于消费进度。
- 素材来源、内容覆盖范围、事实与解读的标注方式。

### 现在预留概念，不急于开发

- 跨版本/改编映射、非连续观看记录。
- 复杂时间线、人物知情范围、伏笔回收。
- 授权视频播放与自动同步。
- 任意作品的自定义模板、插件机制或复杂图数据库。

### 建议下一份设计产物

以同一个原创小故事分别模拟小说、短片、剧集形式，绘制作品入口、内容详情、人物详情、关系详情、地点详情，以及三图联动状态。用同一组例子逐项验证模板，再决定字段和首版范围。
