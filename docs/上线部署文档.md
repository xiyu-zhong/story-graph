## 1. 一句话概览

本仓库是 Next.js 静态导出站点（`output: "export"`），产物在 `out/`，
通过 SSH 上传到阿里云轻量应用服务器，由 nginx 直接托管静态文件。
**线上没有 Node 进程、没有数据库、没有 PM2**，只有 nginx。

因此「上线」= 替换一个目录里的静态文件 + 确保 nginx 配置正确。回滚 = 换回来。

### 2.1 端口与安全

- 只开 **22 / 80 / 443**。80 全部 301 跳到 `https://www.muxixi.xin`。
- ⚠️ 该服务器 sshd **只接受 publickey**，root 密码登录被禁用。
  密钥是唯一入口，`~/.ssh/story-graph-deploy-rsa` 丢了就得走控制台 Workbench 重新写入公钥。
- ⚠️ 端口「放行」≠ 有服务监听。云控制台的防火墙只负责放行，
  443 能不能通还得看 `ss -lntp` 里 nginx 有没有 `LISTEN`。

### 2.2 nginx 配置要点

当前 `/etc/nginx/sites-available/narraverse` 的关键指令：

```nginx
server_name www.muxixi.xin muxixi.xin;
root /var/www/narraverse;
error_page 404 /404.html;

location / {
    rewrite ^/(.+)/$ /$1 permanent;          # ★ 必须保留
    try_files $uri $uri.html $uri/ =404;
}
```

**`rewrite` 去尾斜杠这条不能删。** 静态导出只生成 `xxx.html` 文件，
请求 `/work/condor/` 时 nginx 会当成目录去找 `index.html`，结果 **403**（实测踩过）。

除上述之外，80/443 双 server 块、TLS 证书路径、`options-ssl-nginx.conf` 均由 certbot 托管，
**不要手改带 `# managed by Certbot` 注释的行**。详见 [服务器 HTTPS 配置指南](服务器HTTPS配置指南.md)。

## 5. 发布流程（严格按顺序，不可跳步）

### 步骤 1 — 备份线上现版本

```bash
TS=$(date +%Y%m%d-%H%M%S)
ssh -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes root@www.muxixi.xin \
  "cd /var/www && tar czf /root/backups/story-graph-site-$TS.tar.gz narraverse && \
   sha256sum /root/backups/story-graph-site-$TS.tar.gz && \
   tar tzf /root/backups/story-graph-site-$TS.tar.gz | grep -c ."
```

**再把备份拉回本地**——服务器上只留一份不算备份：

```bash
mkdir -p .workbuddy/backups
scp -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes \
  root@www.muxixi.xin:/root/backups/story-graph-site-$TS.tar.gz .workbuddy/backups/
shasum -a 256 .workbuddy/backups/story-graph-site-$TS.tar.gz   # 与服务器 sha256 比对
```

> 校验和两侧一致才能继续。

### 步骤 2 — 上传到暂存目录

```bash
TS=$(date +%Y%m%d-%H%M%S)   # 本步用的新时间戳
COPYFILE_DISABLE=1 tar czf /tmp/out-$TS.tar.gz -C out .
ssh -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes root@www.muxixi.xin \
  "rm -rf /var/www/.narraverse-new && mkdir -p /var/www/.narraverse-new"
scp -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes \
  /tmp/out-$TS.tar.gz root@www.muxixi.xin:/tmp/
ssh -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes root@www.muxixi.xin \
  "tar xzf /tmp/out-$TS.tar.gz -C /var/www/.narraverse-new && \
   find /var/www/.narraverse-new -type f | wc -l"
```

⚠️ **`COPYFILE_DISABLE=1` 必须加。** 否则 macOS tar 会带上扩展属性，
服务器上会多出一堆 `._*` 垃圾文件。

**比对文件数**：暂存目录的文件数必须与本地 `find out -type f | wc -l` 一致（当前 56）。

### 步骤 3 — 原目录改名保留 + 原子切换

```bash
TS=$(date +%Y%m%d-%H%M%S)
ssh -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes root@www.muxixi.xin \
  "set -e; \
   mv /var/www/narraverse /var/www/narraverse.disabled-$TS; \
   mv /var/www/.narraverse-new /var/www/narraverse; \
   chown -R root:root /var/www/narraverse; \
   nginx -t && systemctl reload nginx; \
   echo SWITCHED_OK"
```

注意这里**不删除**旧目录，只是改名（`narraverse.disabled-<时间戳>`），
保留到确认新版本无问题之后再清理。

### 步骤 4 — 验证（见 §6）

验证通过后，可选清理：

```bash
ssh -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes root@www.muxixi.xin \
  "rm -rf /var/www/narraverse.disabled-<时间戳> /tmp/out-<时间戳>.tar.gz"
```

## 6. 验证清单（四层，缺一不可）

### 第 1 层：服务器侧状态码

```bash
ssh -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes root@www.muxixi.xin \
  'for p in / /work/odyssey /work/journey /work/mortal /work/condor /nonexistent; do
     printf "%-22s " "$p"
     curl -s -o /dev/null -w "%{http_code}\n" --noproxy "*" -m 10 "http://127.0.0.1$p"
   done'
```

期望：五条业务路由 **200**，`/nonexistent` **404**（证明 `error_page 404` 生效）。

### 第 2 层：HTTPS 与跳转

```bash
ssh -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes root@www.muxixi.xin \
  'for h in www.muxixi.xin muxixi.xin $(dig +short www.muxixi.xin); do
     printf "%-18s " "$h"
     curl -s -o /dev/null -w "http=%{http_code} -> %{redirect_url}\n" --noproxy "*" -m 10 "http://$h/"
   done'
```

期望三者 **全部 301 到 `https://www.muxixi.xin/...`**。

### 第 3 层：外网真实可达（★ 服务器自测不算数）

服务器上 `curl https://自己的域名` 走本地回环，**不经过云防火墙，永远成功**，
证明不了外网可达。必须用**外部通道**验证：

```bash
# 用 WebFetch 之类的工具从公网拉取，或本机直接：
curl -sI --noproxy "*" -m 15 https://www.muxixi.xin/ | head -5
curl -s --noproxy "*" -m 15 https://www.muxixi.xin/work/condor?view=map | head -c 200
```

### 第 4 层：真实渲染（★ 唯一能证明部署成功的检查）

**HTTP 200 不代表 JS 能跑、SVG 能画对。** 用 Playwright 打开线上地址真实渲染：

```bash
cd <仓库根> && npx playwright test tests/e2e/map.spec.ts --project=desktop
```

或临时脚本直连线上：

```bash
BASE_URL=https://www.muxixi.xin node scripts/measure-map-collisions.mjs
```

`scripts/measure-map-collisions.mjs` 会真实渲染四部作品的地图并统计标签重叠，
**线上跑出来的数字应与本地一致**（合计：计数压别家标签 9 处、标签互压 9 处）。
数字一致即可证明产物与本地构建等价。

> `npm run test:e2e` 默认打 `http://127.0.0.1:3000`，需要先起 `npm run dev`。
> 要直接测线上，用上面的 `BASE_URL` 方式。

## 7. 回滚

秒级回滚，两条命令：

```bash
ssh -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes root@www.muxixi.xin \
  "set -e; \
   mv /var/www/narraverse /var/www/narraverse.failed-$(date +%Y%m%d-%H%M%S); \
   mv /var/www/narraverse.disabled-<上次时间戳> /var/www/narraverse; \
   systemctl reload nginx; echo ROLLED_BACK"
```

若旧目录已被清理，从备份恢复：

```bash
ssh -i ~/.ssh/story-graph-deploy-rsa -o IdentitiesOnly=yes root@www.muxixi.xin \
  "set -e; rm -rf /var/www/narraverse; \
   tar xzf /root/backups/story-graph-site-<时间戳>.tar.gz -C /var/www; \
   chown -R root:root /var/www/narraverse; systemctl reload nginx; echo RESTORED"
```

> ⚠️ **nginx 配置本身不在上述回滚范围内。** 若问题出在配置（而非产物），
> 要回退 `/etc/nginx/sites-available/narraverse`，
> 备份在 `/root/narraverse.conf.bak-*` 与 `/root/narraverse.conf.redirect-*`。

## 8. 已知坑（全部实测踩过）

| 坑 | 症状 | 解法 |
|---|---|---|
| **去尾斜杠 rewrite 缺失** | 访问 `/work/condor/` 返回 **403** | `rewrite ^/(.+)/$ /$1 permanent;` 必须在 `location /` 里 |
| **macOS tar 扩展属性** | 服务器多出一堆 `._*` 垃圾文件 | 打包前 `COPYFILE_DISABLE=1` |
| **reload 后立刻验证拿到旧配置** | 改完马上 curl 仍是旧行为 | reload 是异步的，旧 worker 还在服务。等几秒或确认 worker `lstart` 已更新 |
| **端口放行 ≠ 有服务监听** | 防火墙已放行 443，`curl https://` 连不上 | 先 `ss -lntp` 确认 nginx 有 LISTEN |
| **zsh 不做变量分词** | `$SSH "cmd"` 报 `no such file or directory` | 用数组 `SSH=(ssh -i ...)`，或干脆把选项写全 |
| **`pgrep -f` 自匹配** | 明明没有该进程却匹配到 | `pgrep -f` 会匹配到自己所在的 shell 命令行。用 `pgrep -x <进程名>` |
| **SSH 命令过长被 SIGTERM** | 退出码 137，输出为空 | 多路由 curl + 长任务合计超时。拆成多次调用 |
| **`out/` 里的 `.txt` 漏传** | 客户端路由跳转异常 | 用 `tar -C out .` 整目录打包，不要挑文件 |

## 9. 安全红线

**密码、密钥、令牌、服务器公网 IP 一律不得进入 git 仓库。** 本仓库是**公开仓库**
（`xiyu-zhong/story-graph`，`visibility: public`），任何写进去的值都会被索引。

因此本文档所有 SSH 命令一律用**域名**（`root@www.muxixi.xin`）而不是裸 IP，
效果完全相同。需要裸 IP 时用 `dig +short www.muxixi.xin` 现场取，不要写回文件。

推送前必做四层审计：

```bash
# 1) 工作区
git status --porcelain
# 2) 被跟踪文件
git ls-files | grep -iE 'env|secret|passw|credential|\.pem|\.key|backup'   # next-env.d.ts 属正常
# 3) ★ 全部 git 历史（最容易漏）
#    私钥头写成正则形式，避免本文件自身命中原样字面量而被 pre-commit 守卫拦下
git rev-list --all | while read c; do
  git grep -I -l -E 'BEGIN [A-Z]+ PRIVATE KEY|ghp_[A-Za-z0-9]{30,}|LTAI[0-9A-Za-z]{12,}' $c 2>/dev/null
done
# 4) ★ 远程仓库实际内容
gh api "repos/<owner>/<repo>/git/trees/main?recursive=1" \
  --jq '[.tree[].path] | map(select(test("env|secret|passw|\\.pem|\\.key|backup";"i"))) | .[]'
```

本地还有两层防护，均已就位并实测：

- `.gitignore`：密钥类（`*.pem` `*.key` `id_rsa*` …）+ 备份类（`backups/` `*.sql.gz` `*.dump`）
- `.git/hooks/pre-commit`：文件名黑名单 + 内容特征扫描，命中即 `exit 1` 阻断

> `.workbuddy/backups/` 与 `.workbuddy/artifacts/` 都在 `.workbuddy/` 下，已被 `.gitignore` 忽略。

**私钥只留在本机 `~/.ssh/`**，绝不上传服务器之外的地方、绝不写入仓库。
