# 《西游记》内容、来源与覆盖说明

## 数据性质

实现位于 `src/data/works/journey.ts`，使用 `import type { Work } from '../../lib/types'`，导出 `export const journey: Work`。

这是依据公版小说自行撰写的中文情节整理，不是原著逐字全文，也不是学术校勘本。包括全部结局与全书剧透。回目保留原有对句，主要依维基文库目录转为简体；摘要、段落、事件、人物介绍、关系依据和地点说明为重新组织的文字。

“完整”只指第1至100回的结构与逐回情节均有内容，不代表原作每段诗赋、每句对白、每场动作都被收录，也不代表已逐字完整审校。小说中的历史、医药、宗教与地理叙述均按文学故事处理，不能直接当作历史考证、医疗建议或实地路线。

| 连续大情节分组 | 31 |

事件的描述与同一场景段落共享已写好的文字，而非再生成一套不同叙事。故事内容全部显式写在 `chapterDrafts`；转换函数仅生成稳定ID、数组关联与类型要求的结构，不向网络运行时拉取正文，也不以重复模板补空缺。

## 来源与核对方法

1. [维基文库《西游记》百回目录](https://zh.wikisource.org/wiki/%E8%A5%BF%E9%81%8A%E8%A8%98)：经过搜索与抓取确认，核对100回顺序与回目。目录列出部分“一作”异文，本整理选其主列回目，不把异文注释误拼入标题。
2. [Project Gutenberg《西遊記》公版电子文本](https://gutenberg.org/cache/epub/23962/pg23962.html)：先搜索确认地址，再下载整部文本，分出100回，逐回核对开头、结尾与故事边界；对移山夺宝、油锅斗法、落胎泉、夜盗兵器、假头骗局、九灵元圣等动作细节另查正文。电子转录有缺字、断行、繁简混用和回目异文，不能把它当无讹定本。
3. [Gutenberg书目记录 #23962](https://www.gutenberg.org/ebooks/23962)：搜索核对书名、语言、发布记录和美国公有领域说明。不是声称所有国家版本及平台附加文字均可无条件复制。
4. [维基文库第九回](https://zh.wikisource.org/zh-hant/%E8%A5%BF%E9%81%8A%E8%A8%98/%E7%AC%AC009%E5%9B%9E)：抓取原文，交叉核对陈光蕊遇害、木板漂江、玄奘认亲与温娇最终自尽的叙述。页面注明清康熙年间汪象旭、黄周星加入附录于此回，故数据的 `editorialNote` 明确此编次差异。
5. [维基文库第九十八回](https://zh.wikisource.org/zh-hant/%E8%A5%BF%E9%81%8A%E8%A8%98/%E7%AC%AC098%E5%9B%9E)：抓取原文，交叉核对凌云渡无底船、脱胎、阿傩迦叶索人事、无字经、紫金钵盂与五千零四十八卷。
6. [维基文库第一百回](https://zh.wikisource.org/wiki/%E8%A5%BF%E9%81%8A%E8%A8%98/%E7%AC%AC100%E5%9B%9E)：抓取原文，交叉核对长安交经、雁塔寺未及开讲即返西天，以及各人的不同果位。没有写成“五位都成佛”。

全部100回关联已定义的目录和公版正文来源；第9、98、100回另关联对应的维基文库原文记录。未猜测或批量拼接未验证的章节深链。全书采用来源级引用，尚未做到每句话对照原文段落或扫描页码。

## 版本与实体约定

- 作者写为吴承恩的传统署名，并保留作者归属存在讨论的说明。
- 第9回采用所用公开本的陈光蕊、江流儿编次；第10回采用目录主列“老龙王拙计犯天条，魏丞相遗书托冥吏”。不能据此断言所有百回版本在这里完全相同。
- 第52回地名以目录中可显示的“金兜洞”呈现；来源指出有缺字、异体问题，不自行补造不存在的字形。
- 人物 `firstChapter` 是该节点在本整理事件中首次关联的回次，不是声称统计原书所有提名、预告、诗句与前身的首次出现。阵营是全书阅读用的主要身份分组，不是随章节动态变化的政治归属。
- 青毛狮子按文殊坐骑身份归并乌鸡国与狮驼岭两段表现，说明写在人物字段中，不将同名坐骑无说明地复制为两个人。
- 陈澄与陈清、七蜘蛛精、玉华三王子、四木禽星用明确标记的群像节点压缩展示。四木禽星中奎木狼在黄袍怪故事另有个人节点，因此组节点与个人节点不是互斥人口统计。
- 关系是全书关系总览，不是“截至所选回”的无剧透状态。关系说明保留旧敌变援手、亲族执法、强占婚姻、私认义亲等条件，`chapterIds` 标出对应依据。
- 类型只提供 `family / ally / mentor / rival / faction`。女王求婚使用 `rival` 标记与取经目标的冲突，并明确她不是妖魔；复杂关系不能仅凭颜色或标签作道德判断。

## 地图与事件关联

所有地点 `x/y` 均为0–100的画布设计坐标。主路分行排布，天庭、地府、南海、海上仙岛等为离线支路，不是实测经纬度、比例尺或导航轨迹。

部分节点合并山、洞、寺、邻村，描述中列明范围；草寇山路、四圣试心松林属于整理用场景标签，并非原著统一正式地名。宝象国附近黑松林归入波月洞区域，无底洞故事的黑松林另建点，避免仅凭同名把两地误当一处。

`Chapter` 使用 `locationIds` 数组；`StoryEvent` 严格遵照类型使用单数可选字段 `locationId`，本数据每个事件都填写了主要地点。一个事件段落有时涵盖赴援、返回等动作，该坐标只代表主要场所。人物关联是事件中的主要参与者，不声称穷尽每位侍从、小妖、神将。

## 已执行的检查

使用项目已有TypeScript编译器，仅检查本文件及其导入的类型，没有安装依赖、启动服务或运行全项目构建：

```sh
./node_modules/.bin/tsc --ignoreConfig --noEmit --strict --skipLibCheck \
  --target ES2022 --module ESNext --moduleResolution bundler \
  src/data/works/journey.ts
```

编译通过。另用本机已有Node 24的类型剥离能力在内存中加载数据，执行断言，全部通过：

- 恰有100回，`order` 连续1–100。
- 每回独立摘要、3段实写情节、3个非空事件，无TODO、待补或占位段。
- 300段正文无完全重复；事件ID全书唯一。
- 章节、人物、关系、地点、来源各自ID唯一。
- 章节及事件人物ID、地点ID均存在，事件关联也包含在本回关联内。
- 全部章节来源ID存在；全部关系端点和依据回次存在。
- `firstChapter` 指向本整理中包含该人物的章节。
- 31个arc各自连续，无交错复用。
- 地图坐标全部在0–100，来源均为有效HTTPS URL格式。
- 固定字段为 `id='journey'`、`unitLabel='回'`、`accent='#f1b969'`、`cover='/art/journey.svg'`、`isFullText=false`。

URL真实性来自前述搜索与抓取，而不是只靠格式检查。没有为这项数据任务创建或修改封面资产，也未验证浏览器中的三视图实际渲染；封面路径按需求填写。只写入本数据实现和本说明文档。

## 实际不足

每回约两百字的三场景复述已经把百回主线铺满，但仍是压缩整理，远少于约八十万字符的所用公版转录。诗赋、修炼寓意、反复试探、次要人物去向及部分残酷情节均有省略；少数多地点事件用单一主要坐标表示。没有完成所有版本异文的校勘、逐句来源定位、完整人物名录、所有关系的时态拆分或浏览器验收。
